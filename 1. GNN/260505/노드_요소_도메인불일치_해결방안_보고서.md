## Executive Summary

### 문제 본질

FEM (유한요소법) 솔버는 **요소(Element)의 적분점(Integration Point, IP)** 에서 응력·변형률을 계산하지만, MeshGraphNet (MGN)은 **노드(Node) 위치**에서 학습한다. 본 논문이 학습 라벨로 사용하는 노드 응력은 **IP → 노드 외삽 + 인접 요소 평균** 의 두 단계 smoothing을 거친 값이라 응력 집중부에서 왜곡된다. 반면 ISO 3006 / KMVSS / 사내 휠 평가는 **요소 von Mises 응력** 기반으로 작동한다. 결과적으로 MGN 예측값을 평가 로직에 직접 투입할 수 없는 도메인 불일치가 존재한다.

## 1장. 문제 정의

### 1.1 FEM과 GNN의 도메인 차이

FEM과 MeshGraphNet의 가장 중요한 도메인 차이는 **물리량의 정의 위치**이다.

| 측면 | FEM (Abaqus) | GNN (MeshGraphNet) |
|---|---|---|
| 변위 (Displacement) | Node에서 정의 | Node(=vertex)에서 학습 |
| 응력·변형률 | **요소의 적분점(IP)** 에서 계산 | Node 위치에서 학습 (외삽 결과) |
| 파단 평가 기준 | **Element von Mises 응력** | (현재) Node 응력 → 평가 부적합 |

본 논문의 백본 모델은 Pfaff et al. (2021) [ICLR]의 MeshGraphNets이며, Encoder–Processor–Decoder 구조에서 **Decoder가 노드 단위 출력**을 가정한다. 이는 GNN의 일반적 설계 관습이지만, 학습 라벨의 물리적 의미와 정합하지 않는다.

### 1.2 노드 응력 외삽 왜곡 메커니즘

Abaqus가 노드 응력을 산출하는 절차 (Abaqus User Manual 24.5.1):

1. 솔버는 element의 **IP(integration point)** 에서 stress tensor를 계산
2. 후처리 시 element의 shape function inverse를 사용해 **IP → element nodes 외삽**
3. 한 노드를 공유하는 인접 요소들의 외삽 stress를 **산술 평균(averaging)**
4. 결과적으로 노드 응력에는 **외삽 + 평균 두 단계 smoothing**이 적용됨

응력 구배가 큰 영역(응력 집중부, 특이점)에서는 외삽 오차와 averaging error가 누적되어 **비현실적으로 작은 값(평균화)** 또는 인접 요소 사이에서 **불연속(왜곡)** 이 발생한다. 본 논문 spoke 영역의 Top-20% region이 정확히 이 응력 집중부에 해당한다.

### 1.3 본 논문 적용 시 발생하는 구체적 문제

- 본 논문 데이터: **85 휠 / 580 샘플 / 노드 200,000~400,000개** (spoke 영역만, 평균 2.4%)
- 본 논문 성능: **Top-20% MAPE 7.0%, KLD 0.005, R²(Top 100%) 0.712**
- 노드당 출력: stress 6 components + deformation 3

문제 1 — **학습 라벨의 정보 손실**: 노드 응력은 외삽 + 평균을 거치므로 GNN이 학습하는 정답 자체가 솔버 원본보다 부정확하다. 본 논문이 보고한 MAPE 7.0%는 노드 averaged stress 기준이며, 만약 element von Mises 기준으로 재평가하면 추가 변환 오차가 누적된다.

문제 2 — **평가 metric 호환성**: ISO 3006:2015의 라디알 피로 / 다이나믹 코너링 / 13° 충격 시험 모두 **element peak von Mises stress vs material yield** 비교를 표준으로 사용한다 (J. Mater. Sci. Mater. Eng. 2026; ResearchGate "Radial Fatigue Analysis ISO 3006"). 본 논문 GNN 출력을 평가 로직에 투입하려면 노드 → 요소 변환이 필요한데, 이 변환이 또다시 averaging 또는 외삽을 요구한다.

문제 3 — **양산 평가 자동화 단순화 어려움**: Hyundai 사내 휠 평가 자동화 파이프라인이 element 응력을 입력으로 가정한다면, GNN 결과를 사용하기 위해 추가 후처리 모듈을 별도 운영해야 한다.

### 1.4 본 보고서의 범위

- **다룬다**: 노드/요소 도메인 불일치를 해결하기 위한 학술 동향(2장), Abaqus 실무 파이프라인(3장), 9개 대안 비교(4장), 추천 1+1 + 6개월 로드맵(5장)
- **다루지 않는다**: 시계열·dynamic transient 처리(260502 D2~D3에서 별도 다룸), Multi-scale GNN(D5), Uncertainty Quantification(D7)
- **연계**: 260502 보고서의 8개 연구방향 중 D1 (SOTA Baseline ablation)에 본 작업이 자연스럽게 흡수된다 (6장 6.4 참조)

## 2장. 학술 동향

본 장은 scout-academic 산출물의 30건 reference를 통합 정리한다. 영역별 분야 분류는 Gemini 3대안에 대응하는 5개 (2.1~2.5) + FEM 물리 명시 통합(2.6) 으로 구성한다.

### 2.1 Element-wise Decoding 발전사 (Gemini 대안 1)

본 영역은 MGN의 노드 단위 디코더를 **요소 단위 출력**으로 교체하는 가장 보수적·구현 단순한 접근이다.

| 저자 (연도) | 출처 | 핵심 |
|---|---|---|
| Maurizi, Gao, Berto (2022) | Sci. Reports 12, 21834 | GN을 메시-그래프로 직접 매핑, 노드 위치에서 stress/strain/displacement 동시 예측. 본 논문 baseline과 가장 유사 |
| Pfaff et al. (2021) | ICLR 2021 [arXiv:2010.03409] | MeshGraphNets — 노드 단위 출력의 baseline. Decoder를 element-aggregator로 교체하는 것이 Gemini 대안 1의 최소 차분 수정 |
| Dalton, Husmeier, Gao (2024) | CMAME [DOI:10.1016/j.cma.2023.116351] | Multi-head: 노드 변위 + 요소 응력. 본 논문 시나리오와 직접 호환 |
| Hernández et al. (2025) | Adv. Model. Simul. Eng. Sci. | Decoder를 multiple specialized decoder로 분리 (energy/entropy gradient + Poisson + dissipative). **multi-decoder가 학습 성능을 향상시킨다는 직접 증거** |

**본 논문 적용 가능성**: Gemini 대안 1은 Pfaff(2021)+Maurizi(2022) 패턴 위에서 decoder만 element-aggregator로 교체하는 가장 보수적 대안이며, Hernández(2025)의 multi-decoder 결과가 **decoder 분리가 성능을 해치지 않는다**는 직접 증거를 제공한다. 학술 정당화 충분성: **상**.

### 2.2 Bipartite / Hypergraph 사례 (Gemini 대안 2)

Gemini가 제안한 단순 Bipartite의 직접 학술 baseline은 약하지만, **node-element hypergraph (FEIH-GNN, Gao 2024)** 가 자연 일반화 형태로 정립되어 있다.

| 저자 (연도) | 출처 | 핵심 |
|---|---|---|
| **Gao, Combescure, Salvi (2024) FEIH-GNN** | J. Comput. Phys. [arXiv:2212.14545, DOI:10.1016/j.jcp.2024.112866] | **node-element 하이퍼그래프**: 노드를 element 단위로 묶고 hypergraph message passing이 local stiffness matrix를 모방. **★ Gemini 대안 2의 학술적 일반화 형태** |
| Cao, Liu (2024) | CMAME | Multi-fidelity hetero graph (coarse/fine 노드 두 종류). PyG 구현 reference |
| Wang, Hsu (2024) | Sci. Reports | edge-augmented multi-GNN. 시간 독립 고체역학에서 MGN 대비 우수 |
| PyG Team | PyTorch Geometric Documentation | Heterogeneous Graph Learning — HeteroData. Gemini 대안 2를 즉시 구현 가능한 framework |

**본 논문 적용 가능성**: 단순 Bipartite는 element 4~8 노드 위상을 모델링할 때 정보 손실 가능성이 있어, **FEIH-GNN의 hypergraph로 일반화 권장**. 그러나 PyG의 hypergraph 지원이 제한적이라 자체 구현 비용 발생. 6개월 로드맵에는 부적합, 후속 연구 (12개월+) 후보.

### 2.3 Dual Graph 사례 (Gemini 대안 3)

본 영역은 학술적으로 가장 명확히 정착된 형태이다. Hestroffer et al. (2025)의 정량 결과(R²=0.992, 150x speedup)가 본 논문 baseline(R²=0.712)을 명백히 상회한다.

| 저자 (연도) | 출처 | 핵심 |
|---|---|---|
| **Storm, Rocha, van der Meer (2024)** | CMAME [arXiv:2402.13101] | "**dual graph over the mesh by connecting integration points**" — IP를 그래프 노드로, IP 간 인접관계를 edge로. ★ 본 논문 문제 본질에 직접 대응 |
| **Hestroffer et al. (2025)** | Comput. Mech. [arXiv:2409.05169, DOI:10.1007/s00466-025-02604-6] | "**mesh cells are converted to nodes**" — Element-as-node, face-shared edge. **R²=0.992, 150배 가속** |
| Lu, Zhang (2025) | Composite Structures [DOI:10.1016/j.compstruct.2025.119353] | Dual-GNN으로 lattice truss의 응력-변형률 곡선 예측. 실험 검증 완료 |
| DG-GNN (2024) | Neural Networks [DOI:10.1016/j.neunet.2024.106788] | DG-FEM의 GNN 구현. element-as-node 매핑이 자연 |

**본 논문 적용 가능성**: 정량 학술 검증 가장 강력. 그러나 **대변형(geometric nonlinearity) 시 element-as-node의 좌표 추적**은 Hestroffer/Storm이 정적·미세 변형에서만 검증했으므로 본 논문 휠 임팩트(동적 거동) 적용 시 **추가 검증 필요** (학술 갭 → 후속 publication 후보).

### 2.4 IP / Gauss point 직접 예측 (Gemini 누락 — 가장 중요)

Gemini는 § 4-4에서 "추가 대안 가능성"으로 짧게 언급했으나, **본 논문 문제 본질("IP에서 응력 계산, Node로 외삽 → 왜곡")의 가장 근본적 해결책**이다.

| 저자 (연도) | 출처 | 핵심 |
|---|---|---|
| **Storm et al. (2024)** | CMAME [arXiv:2402.13101] | **IP를 그래프 노드로 직접 도입** — Abaqus IP raw stress를 변환 없이 학습. SPR 외삽 오차를 원천 차단 |
| Benady (2024) | PhD Thesis (HAL tel-04887187) | IP 단위 constitutive law 학습. GNN은 아니지만 IP-level NN의 reference baseline |

**본 논문 적용 가능성**: IP-as-node 는 본 논문 문제 본질을 직접 해결. **확정 (사용자 피드백 2026-05-07): 본 논문 C3D8 (full integration) 사용** — 8 IP/element 로 데이터 부피 6~8× 증가, 학습 비용 +150~200%, B=2 → B=1 강제, 메모리 50~60 GB → **6개월 로드맵 outside**. (참고) C3D8R 가정 시 IP 부피가 centroid 와 동급이라 실무 적용 가능했으나 본 논문 환경 미적용. **5장 추천 #2 는 A3 Dual Graph (Element-as-Node, centroid 기반) 로 차선 채택**.

### 2.5 Edge / Face attribute regression (Gemini 누락)

응력 텐서는 본질적으로 **요소 face에서 traction**으로 나타나므로, edge-attribute regression은 face flux 보존을 강제할 수 있어 **물리적으로 가장 정합적**이다.

| 저자 (연도) | 출처 | 핵심 |
|---|---|---|
| Horie & Mitsume (2024) FluxGNN | arXiv:2405.16183 | Face flux를 edge attribute로 학습. **conservation law 보존** |
| Praditia et al. (2024) | arXiv:2508.19052 | FVM 스킴을 edge-level로 학습. Edge attribute regression의 일반화 |
| Gong & Cheng (2019) | CVPR 2019 | Edge feature 활용 GNN의 foundation |

**본 논문 적용 가능성**: 학술적으로 우아하지만 MGN 대규모 변경 필요. Abaqus의 face-level traction 추출은 비표준이라 자체 후처리 필요. **본 논문 6개월 로드맵에는 부적합, 후속 연구 (24개월+) 권장**.

### 2.6 FEM 물리 명시 통합 (B-matrix, equilibrium loss)

| 저자 (연도) | 출처 | 핵심 |
|---|---|---|
| **Zhang et al. (2024/2025) FEINN** | CMAME 433 [DOI:10.1016/j.cma.2024.117474] | **B-matrix·shape function·Gauss integration을 NN loss에 명시 통합**. weak form 잔차로 학습. **MAPE < 1% vs FEM** |
| **Thel et al. (2024) FEMIN** | CMAME 427:117073 [DOI:10.1016/j.cma.2024.117073] | NN을 FEM solver 내부에 직접 통합. **Crash 시뮬레이션 8,550배 가속**. 본 논문 휠 임팩트와 도메인 일치 |
| **Maia & van der Meer (2025) P-DivGNN** | arXiv:2507.05291 | **Equilibrium loss (div σ = 0)** 를 GNN 학습에 명시 통합. Multi-head decoder + 물리 loss. 본 논문에 즉시 차용 가능한 **plug-in** |
| Pyrialakos & Triantafyllou (2022) I-FENN | CMAME 397 | Damage 변수 NN + FEM solver 결합. 파단 평가 직접 연관 |

**본 논문 적용 가능성**: P-DivGNN의 equilibrium loss(‖div σ‖²) 항은 모델 구조 변경 없이 **plug-in 수준 (5% 추가 코드)** 으로 부착 가능 → 추천 #1 (A1+EQ)의 핵심 학술적 강화 요소. FEMIN/FEINN은 본 논문 도메인과 가장 가깝지만 Abaqus user subroutine (UEL/UMAT) 통합이 필요해 양산 도입 부담이 크다.

### 3.2 FEM Stress Recovery 알고리즘

| 알고리즘 | 출처 | 본 논문 적용 비용 | 효용 |
|---|---|---|---|
| **SPR** (Superconvergent Patch Recovery) | Zienkiewicz, Zhu, IJNME 1992 | IP raw 추출 + patch fitting 코드 (~200~500줄) | **낮음** — Abaqus 노드 외삽이 이미 유사 averaging 수행 |
| **L2-projection** | 변분원리 | mass matrix solve | 낮음 — 후처리 비용 |
| **Volume-weighted averaging** | 일반 | element 부피 추가 추출 | **중간** — 노드 라벨 품질 향상 |
| **Element centroid 직접 학습** | scout-practical 권장 | 스크립트 1줄 변경 | **높음** — 도메인 불일치 근본 해결 |

**권장**: SPR/L2-projection은 GNN 학습 paradigm과 결이 달라 우선순위 낮음. 데이터 추출 단계에서 **centroid 또는 IP를 직접 사용**하는 것이 보다 직접적이다.

### 3.5 ISO 3006 / KMVSS 평가 metric 정합성

ISO 3006:2015 (Road vehicles — Passenger car wheels — Test methods)는 라디알 피로, 다이나믹 코너링 피로, 13° 충격 시험 3종을 정의하며, FEA 기반 평가는 모두 **element peak von Mises stress vs material yield** 비교를 표준으로 사용한다 (J. Mater. Sci. Mater. Eng. 2026).

| GNN 출력 형식 | 평가 직접 투입 | 변환 필요 |
|---|---|---|
| Node averaged stress (현재) | **불가** | element averaging 추가 변환 (정보 손실 누적) |
| Node unaveraged stress (per element) | 가능 | element 평균 1단계 |
| **Element centroid stress** | **가능 (직접)** | 없음 |
| **Element von Mises (직접 출력)** | **가능 (즉시)** | 없음 |
| IP raw stress | 가능 | element 대표값 산출 (max/avg) |

**결론**: **본 논문 baseline의 노드 응력 출력은 평가 단계에서 한 번 더 변환이 필요**, 이는 GNN 예측 오차 + 변환 오차 누적을 의미한다. element 위치 출력으로의 전환이 평가 호환성 측면에서 절대적으로 우월.

## 4장. 대안 비교 분석

### 4.1 검토 대안 9개 (정의 + 학술/실무 ref 매핑)

본 절은 analyst-alternatives의 9건 대안 정의를 압축 정리한다. 상세 설명은 부록 B 참조.

- **A1. Element-wise Decoding**: MGN encoder/processor 유지 → decoder 단계에서 element를 구성하는 노드들의 잠재 vector를 pooling → element MLP. 노드는 변위 head 유지(multi-head). 변형 5종: avg / max / volume-weighted / shape-weighted / **A1+EQ (P-DivGNN equilibrium loss 추가)**.
- **A2. Bipartite Graph**: PyG HeteroData로 Node·Element 두 종류 vertex. Node→Element / Element→Node 두 단계 message passing.
- **A2'. Hypergraph (FEIH-GNN)**: Element가 hyperedge로 4~8 노드 묶음. Hypergraph message passing이 local stiffness matrix 모방.
- **A3. Dual Graph (Element-as-Node)**: Element를 graph node, face-shared element끼리 edge. Hestroffer 2025 R²=0.992.
- **A4. IP-as-Node (Storm 2024)**: Integration point를 그래프 노드로 직접 도입. C3D8 (full int.) vs C3D8R (reduced int.) 분기.
- **A5. Edge/Face-attribute regression**: 응력 텐서를 element face traction으로 표현. Conservation law 강제.
- **A6. Equilibrium-loss plug-in (P-DivGNN)**: A1 또는 A2 위에 ‖div σ‖² 추가. plug-in 수준.
- **A7. NN-in-Solver hybrid (FEMIN/FEINN)**: NN을 Abaqus user subroutine 통합. 양산 부담 큼.
- **A8. Hybrid SPR + 학습**: 노드 응력 학습 후 SPR-aware projection.
- **A9. Centroid-only direct training**: 데이터 라벨만 centroid stress로 교체 (가장 단순 ablation).

### 4.3 Gemini 3대안 비판적 평가

#### 대안 1 (Element-wise Decoding) — Gemini 추천

- **강점**: baseline 재활용율 90%+. 학술 ref 4건. Altair physicsAI Multi-Head 패턴과 일치.
- **약점**: **Pooling 함수 선택 정당화 약함** (학술 ablation 0건). Loss weighting w₁/w₂ 직관 의존. 평형방정식 잔차 같은 **물리 prior 부재**.
- **본 보고서 보강**: **A1+EQ로 강화** — P-DivGNN equilibrium loss plug-in 추가 시 학술 신규성 중→상, 재활용율은 85%+로 거의 유지.

#### 대안 2 (Bipartite Graph)

- **강점**: PyG HeteroData로 즉시 구현. 노드/요소 역할 명시 분리.
- **약점**: **단순 bipartite의 직접 학술 ref 약함**. baseline 재활용율 60~70%, 비용 대비 효용 미약. element 4~8 노드 위상 모델링 시 정보 손실 가능.
- **본 보고서 보강**: **A2'로 일반화 권장** — FEIH-GNN(Gao 2024)의 hypergraph 형태가 학술적으로 강력. 단, PyG 지원 제한 + 자체 구현 비용으로 6개월 로드맵에는 무리.

#### 대안 3 (Dual Graph)

- **강점**: Hestroffer 2025 R²=0.992, 150× speedup — 정량 학술 검증 가장 강력. spoke 위상학과 부분 일치.
- **약점**: **변위 예측 별도 모델 필요**. **대변형(geometric nonlinearity) 시 element-as-node 좌표 추적 학술 갭** (정적·소변형 검증만 보고됨). baseline 재활용율 30~40%.
- **본 보고서 보강 (2026-05-07 v2)**: **본 논문 C3D8 (full integration) 확정으로 A4 (IP-as-Node) 가 6개월 outside → A3 단독을 추천 #2 로 격상**. 본 논문 휠 임팩트(동적·대변형) 검증이 정적 baseline (Hestroffer 2025 polycrystal R²=0.992 / Storm 2024) 의 명확한 미답 영역을 채우는 contribution 으로 전환 → CMAME publication 직접 명분.

#### 구현 단계 (Step 1~6, 8~10주)

본 절은 핵심 단계만 압축 제시한다. 상세 의사코드는 **부록 C** 참조.

```
Week 1~2: 데이터 추출 변경 (S3 시나리오)
  - Abaqus odb 스크립트에 getSubset(position=CENTROID) 추가 (3~5줄)
  - 580 샘플 × element centroid stress 6 components 추가 추출
  - element label → element node mapping 테이블 산출
  - 한 샘플에서 노드 averaged stress vs centroid stress 분포 비교 (응력 집중부 차이 확인)

Week 3~4: Multi-Head Decoder 구현
  - MGN baseline final decoder MLP를 두 head로 분리:
      head_node (변위 3) — 기존 baseline 보존
      head_element (응력 6 또는 von Mises 1) — 신규
  - Pooling: volume-weighted 우선
      h_E = Σ_i (V_i / V_E) · h_node_i
  - Loss: L = w₁ ‖u_node‖² + w₂ ‖σ_element‖²
  - 코드 추가 ~30~50줄

Week 5~6: Equilibrium-loss plug-in
  - div σ_E = (1/V_E) ∮_∂E σ · n dA  (Gauss-Green 면적분 우회로 B-matrix 회피)
  - L += w₃ ‖div σ‖² (외력 0인 spoke 영역 한정)
  - w₃ warm-up: epoch 0~500은 0, 500~1000 선형 증가
  - 코드 ~80~120줄

Week 7~8: Pooling ablation + 평가 metric 확장
  - A1-avg / A1-max / A1-volume-weighted / A1-shape-weighted 4종 비교
  - Top-20% MAPE / KLD / R² (element-level) 측정
  - element von Mises 직접 출력 → ISO 3006 평가 로직 직접 투입

Week 9~10: 보고서 / 후속 paper draft
  - 본 논문 D1 ablation에 통합
  - JSAE/SAE workshop draft 초안
```

### 5.2 중기 학술 publication — 추천 #2: A3 Dual Graph (Element-as-Node)

#### 5.2.1 대안 명칭 및 근거

- 6축 매트릭스 종합 점수 **33.5/45 (C3D8 환경 현실 가능 대안 중 추천 #1 다음 2위)**

  - **★ Hestroffer 2025** (Comp.Mech, R²=0.992, 150× speedup, polycrystal **정적**) — 가장 강한 정량 학술 검증
  - **Storm 2024** [CMAME] — Microstructure-based GNN
  - Lu 2025 (Composite Structures) — lattice truss 검증, 본 논문 spoke 위상학 부분 일치
  - DG-GNN 2024 (Neural Networks) — DG-FEM 이론적 근거

- **C3D8 영향 없음**: centroid 추출 (시나리오 S1) 사용 → IP 추출 부담 회피

## 6장. 결론

### 6.1 종합 평가

본 보고서는 MeshGraphNet 의 노드/요소 도메인 불일치 문제를 9개 대안으로 체계화하고, 학술·실무 통합 평가를 통해 **A1+EQ (단기 Quick Win) + A3 Dual Graph (중기 학술 publication)** 의 추천 1+1 을 도출했다. *(2026-05-07 v2 갱신: 사용자 피드백으로 본 논문 element type C3D8 (full integration) 확정 → 추천 #2 를 A4-C3D8R 에서 A3 Dual Graph 로 교체)*. 핵심 발견은 다음 3가지이다:

1. **Gemini 대안 1 (Element-wise Decoding) 이 가장 합리적**이지만 P-DivGNN equilibrium loss plug-in 을 부착(A1+EQ)하면 학술 신규성이 중→상으로 상승하면서도 baseline 재활용율 85%+ 를 유지한다.
2. **본 논문 C3D8 (full integration) 확정으로 IP-as-Node (Storm 2024) 직접 학습은 6개월 outside** — 학습 비용 +150~200%, B=2 → B=1 강제, 메모리 50~60 GB. 따라서 차선 경로로 **A3 Dual Graph (Element-as-Node)** 가 채택됨. centroid 추출 사용 → C3D8 영향 없음, Hestroffer 2025 (R²=0.992 polycrystal **정적**) / Storm 2024 [CMAME] 학술 baseline + 본 논문이 **대변형 동적 임팩트 + 양산 휠 (200~400k 노드)** 학술 갭 보강 → CMAME publication 직접 명분.
3. **본 논문 element type 분기점은 사용자 피드백으로 확정됨 (C3D8)** — Gemini 답변에서 누락된 핵심 분기점. 이로 인해 추천 #2 가 IP-as-Node 직접 학습에서 element-level 우회 경로로 전환되었으나, 학술 신규성·정량 근거는 Hestroffer/Storm baseline 의 미답 영역(동적 대변형) 보강으로 오히려 강화됨.

### 6.4 260502 D1~D8 로드맵과의 연계

본 보고서의 추천 #1 (A1+EQ) 과 추천 #2 (A3 Dual Graph) 는 260502 보고서의 8개 연구방향 (D1~D8) 과 다음과 같이 연계된다 *(2026-05-07 v2 갱신: 추천 #2 = A3 Dual Graph 기준 재정리)*:

| 260502 연구방향 | 본 보고서와의 관계 | 시너지 |
|---|---|---|
| **D1. SOTA Baseline ablation** | 본 추천이 D1의 한 항목으로 자연 흡수 | A1-avg/max/volume/shape 4종 + A1+EQ + A3 Dual Graph 의 ablation 매트릭스가 D1의 "label/decoder ablation" 섹션을 채움 |
| D5. Multi-scale GNN | 추천 #2 (A3) 의 element graph + A1+EQ 의 node graph 가 multi-scale 융합 가능 | 부분 시너지 (element → node → coarse mesh 3-scale) |
| D2~D4 (시계열, 동적, transient) | 직접 연계 약함 | **추천 #2 (A3) 의 대변형 동적 임팩트 검증 (학술 갭 직접 공략) 이 D3 (Dynamic transient) 와 강한 연계** |
| D6 (Geometry-aware) | 본 논문 baseline이 이미 채택 | 신규 연계 약함 |
| D7 (UQ) | 직접 연계 약함 | 장기 옵션 (A4-C3D8 부분 sampling) 의 IP-level 분포로 UQ 확장 가능 |
| D8 (Foundation models) | 직접 연계 약함 | A1+EQ 의 Multi-Head 구조가 foundation model 의 multi-task head 와 양립 |

**결론**: 본 보고서는 260502 D1 을 보강하는 첫 번째 큰 ablation 항목으로 즉시 활용 가능하며, 추천 #2 (A3 Dual Graph) 완성 시 **D3 (Dynamic transient) + D5 (Multi-scale GNN) 와의 자연 융합 경로**가 열린다 (Hestroffer/Storm 정적 baseline → 본 논문 동적 검증).

### C.2 Multi-Head Decoder (PyTorch)

```python
import torch
import torch.nn as nn
from torch_scatter import scatter

class MultiHeadDecoder(nn.Module):
    """
    A1+EQ Decoder.
    head_node: 노드별 변위 (3) - 기존 baseline 보존
    head_element: element별 von Mises 응력 또는 stress 6-comp
    """
    def __init__(self, hidden_dim=64, out_node=3, out_elem=6):
        super().__init__()
        self.head_node = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, out_node),
        )
        self.head_elem = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, out_elem),
        )

    def forward(self, h_node, elem_to_nodes_idx, node_volumes_per_elem, V_elem):
        # h_node: (N_nodes, hidden_dim)
        # elem_to_nodes_idx: (E*K,) — flattened. K=8 for C3D8.
        # node_volumes_per_elem: (E*K,) — V_i (i번째 노드 인접 부분 부피)
        # V_elem: (E,) — 요소 부피

        # head_node: 노드 단위 변위
        u_pred = self.head_node(h_node)  # (N_nodes, 3)

        # Volume-weighted pooling: h_E = Σ_i (V_i / V_E) · h_node_i
        # E*K 만큼 expand 후 weighted sum
        weights = node_volumes_per_elem / V_elem.repeat_interleave(K)
        h_node_for_elem = h_node[elem_to_nodes_idx]  # (E*K, hidden)
        weighted = h_node_for_elem * weights.unsqueeze(-1)
        elem_idx = torch.arange(V_elem.shape[0]).repeat_interleave(K)
        h_E = scatter(weighted, elem_idx, dim=0, reduce='sum')  # (E, hidden)

        sigma_pred = self.head_elem(h_E)  # (E, 6)
        return u_pred, sigma_pred
```

### C.3 Loss Function (Multi-task + Equilibrium)

```python
def loss_fn(u_pred, u_gt, sigma_pred, sigma_gt,
            edge_index_face, area_face, normal_face, V_elem,
            w1=1.0, w2=1.0, w3=0.0):
    """
    L = w1 ||u_pred - u_gt||^2 + w2 ||sigma_pred - sigma_gt||^2
        + w3 ||div sigma||^2 (equilibrium-loss plug-in, P-DivGNN)
    Gauss-Green 면적분 우회: div sigma_E = (1/V_E) Σ_{f∈∂E} (sigma_E - sigma_neighbor) · n · A_f
    """
    L_node = ((u_pred - u_gt) ** 2).mean()
    L_elem = ((sigma_pred - sigma_gt) ** 2).mean()

    # Equilibrium-loss (외력 0 영역만)
    if w3 > 0:
        # edge_index_face: face shared element pair (E_a, E_b)
        # 각 face에서 sigma · n 의 차이 = traction discontinuity
        sigma_a = sigma_pred[edge_index_face[0]]  # (F, 6)
        sigma_b = sigma_pred[edge_index_face[1]]
        traction_jump = compute_traction_jump(sigma_a, sigma_b, normal_face) * area_face
        # 각 element별 face 적분 합산 후 V_E로 정규화
        div_sigma = scatter(traction_jump, edge_index_face[0], dim=0, reduce='sum') / V_elem
        L_eq = (div_sigma ** 2).mean()
    else:
        L_eq = 0.0

    return w1 * L_node + w2 * L_elem + w3 * L_eq
```

def build_element_graph(elem_data):
    """
    Mesh connectivity 로부터 element-as-node graph 구축.
    edge: face-shared element 쌍 (Tri/Quad/Tet/Hex 통일 처리).
    Output: (V', E', face_areas, face_normals)
    """
    # Step 1. element → face 분해 (element type 별 표준 face 정의)
    elem_faces = {}  # elem_label -> set of frozenset(face_node_ids)
    for label, etype, nodes in elem_data:
        elem_faces[label] = decompose_faces(etype, nodes)
        # C3D8: 6 faces, C3D4: 4 faces, etc.

    # Step 2. face → 인접 element pair 사상 (hash table)
    face_to_elems = {}  # frozenset(node_ids) -> [elem_label, ...]
    for label, faces in elem_faces.items():
        for face in faces:
            face_to_elems.setdefault(face, []).append(label)

    # Step 3. 동일 face 공유하는 element 쌍 → edge
    edges = []
    face_areas = []
    face_normals = []
    for face, elems in face_to_elems.items():
        if len(elems) == 2:  # face-shared
            edges.append((elems[0], elems[1]))
            face_areas.append(compute_face_area(face))
            face_normals.append(compute_face_normal(face))

    return edges, face_areas, face_normals

```python
class ElementGraphMGN(nn.Module):
    """
    Element-as-Node MGN. baseline encoder/processor 골격 유지.
    입력: element centroid 좌표, 부피, element type, 재료 물성
    출력: element von Mises stress (직접) + 6 stress components
    """
    def __init__(self, hidden_dim=64, num_layers=20):
        super().__init__()
        # Encoder: element feature → hidden (재활용 60%)
        self.encoder = nn.Sequential(
            nn.Linear(IN_FEAT_DIM, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim),
        )
        # Processor: MGN message passing on element graph (재활용 70%)
        self.processor = nn.ModuleList([
            MGNBlock(hidden_dim) for _ in range(num_layers)
        ])
        # Decoder: element 단위 출력 (신규, 재활용 30%)
        self.decoder = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, 7),  # 6 stress + 1 von Mises
        )

    def forward(self, x_elem, edge_index, edge_attr):
        # x_elem: (E, IN_FEAT_DIM) — centroid coords + volume + etype + material
        # edge_index: (2, F) — face-shared element pairs
        # edge_attr: (F, EDGE_DIM) — face area, normal, distance
        h = self.encoder(x_elem)
        for block in self.processor:
            h = block(h, edge_index, edge_attr)
        return self.decoder(h)
```
