## A. Equilibrium-loss Plug-in 설명

### 1. 개념 — 물리 법칙을 손실함수에 직접 박기

정적 구조물에는 **체적력이 없는 영역에서 응력 발산(divergence)이 반드시 0이어야 한다**는 물리 법칙이 있습니다.

```
div σ = 0   ← 정역학적 평형방정식 (외력 없는 내부 영역)

풀어쓰면:
∂σ_xx/∂x + ∂σ_xy/∂y + ∂σ_xz/∂z = 0  (x방향)
∂σ_yx/∂x + ∂σ_yy/∂y + ∂σ_yz/∂z = 0  (y방향)
∂σ_zx/∂x + ∂σ_zy/∂y + ∂σ_zz/∂z = 0  (z방향)
```

FEM 솔버는 이 조건을 **수치적으로 강제**합니다. 그러나 GNN은 이 사실을 전혀 모르고 **데이터만 보고 학습**하기 때문에, 예측 응력장이 이 조건을 위반할 수 있습니다.

Equilibrium-loss는 이 잔차를 손실함수에 추가 항으로 넣어서, **GNN이 물리적으로 말이 되는 응력장을 예측하도록 패널티를 주는 것**입니다.

```
L_total = w1·L_변위 + w2·L_응력 + w3·‖div σ‖²
                                    ↑
                            이 항이 Equilibrium-loss
```

출처는 Maia & van der Meer (TU Delft, 2025), **P-DivGNN** (arXiv:2507.05291) 입니다.

---

### 2. 왜 필요한가 — GNN의 구조적 맹점

**상황**: GNN은 학습 데이터의 응력 값은 잘 따라가지만, 예측 결과가 물리적으로 자기모순을 일으킬 수 있습니다.

예를 들어 이런 상황이 발생합니다:
- 인접한 두 요소의 예측 응력이 경계면에서 트랙션(traction)이 연속되지 않음
- 내부 어느 지점에서 응력이 외부 하중 없이 갑자기 발산
- MAPE는 낮아도 파단 위험 영역 주변에서 국소적 평형 위반

이것이 **본 논문의 핵심 문제인 "노드-요소 도메인 불일치"와 직접 연결**됩니다:

```
현재 학습 흐름:
  FEM → IP 응력 → 노드로 외삽·평균 → GNN 학습 라벨
                      ↑
               이미 평형 정보가 흐릿해진 상태

Equilibrium-loss가 하는 일:
  GNN 예측 자체에 div σ = 0 을 직접 감시 → 외삽 왜곡을 일부 보정
```

---

### 3. 작동 원리 — Gauss-Green 면적분 이산화

`div σ`를 직접 미분으로 계산하면 연속체 가정이 필요해 메시에서 쓰기 어렵습니다. P-DivGNN은 **발산 정리(Gauss-Green theorem)** 로 우회합니다.

```
발산 정리: ∫_V div σ dV = ∮_∂V σ · n dA

요소 단위로 이산화하면:
div σ_E ≈ (1/V_E) × Σ_{f ∈ 요소 E의 면들} (σ_E · n_f) × A_f
```

실제 코드(보고서 C.3)에서는 이것을 인접 요소 간 **트랙션 점프(traction jump)** 로 근사합니다:

```python
# 공유 면(face)을 사이에 둔 두 요소 E_a, E_b
sigma_a = sigma_pred[edge_index_face[0]]   # E_a 예측 응력 (F, 6)
sigma_b = sigma_pred[edge_index_face[1]]   # E_b 예측 응력 (F, 6)

# 면에서의 트랙션 불연속 = 평형 위반의 직접 척도
traction_jump = (σ_a - σ_b) · n · A_f

# 요소별 모든 면 합산 후 체적 정규화
div_sigma_E = Σ(traction_jump) / V_E

# 손실 항
L_eq = mean(div_sigma_E²)
```

**직관**: 이웃한 두 요소 경계면에서 응력이 연속적이면 → 트랙션 점프 ≈ 0 → L_eq ≈ 0. 경계면에서 응력이 불연속이면 → 평형 위반 → 패널티.

---

### 4. 학습 안정성 — Warm-up 스케줄링

초기부터 w3를 크게 주면 학습이 불안정해집니다 (데이터 학습이 채 안 된 상태에서 물리 조건을 강요하면 gradient 충돌). 그래서 **P-DivGNN 방식**을 차용합니다:

```
epoch    0 ~ 500  : w3 = 0     (데이터로만 학습, 모델 안정화)
epoch  500 ~ 1000 : w3 선형 증가 (물리 조건 서서히 강화)
epoch 1000 ~      : w3 = 0.1   (풀 강도)
```

---

### 5. "Plug-in"이라고 부르는 이유

모델 구조(Encoder / Processor / Decoder) 를 **전혀 건드리지 않습니다**. 손실함수에 항 하나를 추가하고, 학습 루프에서 w3 스케줄러를 넣는 것이 전부입니다.

보고서에서 **"5% 추가 코드"** 라고 표현한 이유이며, 추천 #1 (A1+EQ) 에서 Element-wise Decoding 위에 얹는 방식으로 baseline 코드 재활용율 85%+를 유지하면서 학술 신규성을 **중 → 상**으로 높이는 핵심 요소입니다.
